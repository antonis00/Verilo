# Verilo: project context

A personalised English-language newspaper, web first (mobile later), built by one developer. It groups articles about the same event into **stories**, ranks stories per reader, and shows checked AI summaries that cite their sources. Free trial, then a subscription. The full design is in `docs/design.md`; the visual rules in `docs/style-guide.md`.

## Phases (stop for the owner's review after each: tests pass, commit, push)
1. Plan and scaffold: done.
2. Source ingestion: done (see "Sources and ingestion" below).
3. Story grouping: done (see "Stories, opinion and topics" below).
4. AI summaries with checks: only with 3+ trusted outlets of different leans; a second model checks each summary against the snippets; any failure shows headlines and links only and is logged. Also planned here: a Claude Haiku topic tagger to raise topic coverage (the embedding matcher only assigns confident matches).
5. Personal feed and digest. Done first, at the owner's request (before 4): the front page, story pages, the welcome wizard, settings and the ranked personal feed (see "Readers, front page and preferences"). Still to do: the daily digest page and the free-trial flag.

Order agreed with the owner (Nov 2026): 5a (done) → 4 → rest of 5.

## Non-negotiable rules
- **Never store or show full article text.** Headline, a snippet of at most 400 characters (`workers/verilo_workers/common/snippet.py`, enforced again by the database), the outlet, the link and the date. No scraping past a feed, no paywall bypassing.
- **Never invent facts.** Every summary point names the source articles it came from and must be supported by their snippets. When outlets disagree, say who reports what. If a check fails, show headlines and links instead.
- **Opinion is never a source of facts.** Opinion, editorials and sponsored pieces are labelled and kept out of summaries.
- **Favour reputable, balanced sources.** Summaries use only Tier 1–2 outlets, including a wire service or public broadcaster and at least two lean groups. Lean labels are shown to readers.
- **Label AI text** as "AI summary", with a link to each source within one tap.

## Stack
- `apps/web`: Next.js **16** (App Router, TypeScript strict, Cache Components and Partial Prefetching on), Tailwind v4 with only our tokens, Supabase via `@supabase/ssr`. Next 16 differs from older versions: read `apps/web/node_modules/next/dist/docs/` before using an API (see `apps/web/AGENTS.md`). In particular:
  - Middleware is `proxy.ts` (`lib/supabase/proxy.ts` refreshes the session and guards `/my-news`).
  - Anything that reads cookies, headers or `searchParams` must sit inside `<Suspense>`, or the build fails. Pages are a static shell with the reader's parts streamed in; keep it that way (don't await the session at the top of a layout).
  - Who the reader is comes only from `lib/auth.ts` (`getReader`, `requireReader`, `requireEditor`). Every page and server action checks the session itself; the proxy check is only a shortcut.
  - A page that has started streaming can't change its status code: a request-time 404 or redirect belongs in the proxy (`/desk` answers a real 404 to non-editors there). Read the clock through `lib/request-time.ts`, never `Date.now()` in a component.
- `supabase/`: local Supabase (CLI 3.2, pinned in the root `package.json`, Postgres 17). Database changes only as SQL in `supabase/migrations/`. Row-level security on every table readers touch. Unused services are off in `config.toml`. Local emails go to Mailpit (http://127.0.0.1:54324).
- Sign-in: an emailed link (`supabase/templates/magic_link.html`) to `/auth/confirm`, which verifies the token hash on the server (`verifyOtp`). `lib/safe-next.ts` keeps redirects on this site.
- `workers/`: Python 3.12+ package `verilo_workers` (ingest, enrich, cluster, summarize, common). Plain `venv` + `pip install -e ".[dev]"`; Ruff and pytest.
- Models (when used, phases 3–4): Claude Haiku 5.5 (`claude-haiku-5-5`) for tagging and writing summaries, Claude Sonnet 5.5 (`claude-sonnet-5-5`) to check them, through the official `anthropic` Python SDK. Embeddings: local `fastembed` (`bge-small-en-v1.5`, 384 dimensions), the owner's choice (Nov 2026); keep the embedding call behind one function so Voyage could replace it if grouping quality measured on real headlines falls short.

## Sources and ingestion
- **Regions:** every outlet has a country and the region it counts for (`REGION_OF` in `ingest/registry.py`: North America, UK and Ireland, Europe, Middle East, Africa, South Asia, East Asia, Southeast Asia, Oceania, Latin America; "international" for outlets with no home, not offered to readers). A source can override its region when it covers another one (`region = "middle-east"` for Al-Monitor in Washington). The same lists are in the database constraints (migration `…07`) and `apps/web/lib/regions.ts`; `test_the_database_accepts_every_country_and_region_the_registry_knows` keeps them in step. Readers' "Places" are regions (`reader_preferences.regions`); ranking lifts stories by the share of their outlets from the chosen regions. Nov 2026: 78 outlets, 70 active, with reputable (tier 1–2) outlets in every region; leans are on the US/UK scale and nominal for most outlets outside it, and state ownership or funding is stated in each `basis` (Al Jazeera, The National, SCMP, Straits Times...).
- **The registry is `workers/data/sources.toml`** (the owner edits it; `python -m verilo_workers sync-sources` writes it to the database). Each outlet: tier (1 fact base, 2 reputable, 3 labelled and never summarised), lean (left / lean_left / center / lean_right / right), kind, country, `basis` (why that tier and lean), `reviewed` (date the owner checked them; empty until then), `status` (active / paused / excluded) with a `note` saying why when paused, and its news feeds with a poll interval.
- The first tiers and leans (Nov 2026) are a proposal from general knowledge of public ratings (AllSides, Ad Fontes), not checked line by line against them; the owner reviews each. Ratings providers' own scores are not shown in the app until their licences are checked.
- Wire services (Reuters, AP, AFP) publish no public RSS; public broadcasters (BBC, NPR, PBS, CBC, ABC Australia, SBS, RTÉ) are the fact base. Outlets whose robots.txt disallows crawlers (The Times, Axios, The Australian, National Post, CTV, TheJournal.ie) or whose feeds are dead (WSJ, CNN since Aug 2024) are paused with the reason. CBC's robots.txt doesn't answer from the development machine (connection reset); the fetcher skips it until it does.
- `python -m verilo_workers check-feeds` tries every active feed and reports, storing nothing: run it before adding a source.
- `ingest` fetches the feeds that are due (`--all` for every feed, `--source slug` to limit, `--loop` to keep going every minute). Politeness: robots.txt per site (RFC 9309: missing allows, an error or no answer means not now), `VeriloBot/0.1 (+https://github.com/antonis00/Verilo)` as the user agent (until there's a domain), conditional requests (ETag / Last-Modified), one request at a time per site, 5 MB limit, backoff doubling per failure up to a day. TLS checks against the Windows certificate store too (truststore), because antivirus HTTPS inspection on this machine re-signs certificates.
- Parsing keeps the headline, a snippet from the item's summary (never `content:encoded`), the link without tracking parameters, and the date. Items with no date, older than 7 days or with non-web links are skipped; future dates become now. Duplicates: the same URL, or the same headline from the same outlet on the same day (`content_hash`).
- Tables (`supabase/migrations/…02_sources_and_articles.sql`): `sources`, `source_feeds`, `articles` (no article-text column; length checks on title and snippet), `fetch_log` (30 days). Sources and articles are readable by anyone; feeds and the log by editors only; only the workers write. `profiles.is_editor` (readers can update only their name and time zone) opens `/desk`: `python -m verilo_workers make-editor you@example.com`.
- `/desk` (editors only): the latest articles with outlet, tier, lean and age, and every source's feed health and review status.

## Stories, opinion and topics
- **Kind** (`workers/verilo_workers/enrich/kind.py`, decided at ingest): `news`, `opinion` or `sponsored`, with `kind_reason` naming the rule in plain words (shown on the desk). Rules: link path segments (`/opinion/`, `/commentisfree/`, `/review/`, `/shopping/`…), headline formulas ("The Guardian view on…", "| Letters", "Review:"), and the feed's categories, but only explicit labels (a "Shopping" topic tag on an opinion column is not paid content). Only `news` may feed a summary. A wrong call: add a test case in `tests/test_kind.py`, then fix the rule.
- **Embeddings** (`enrich/embed.py`, the only place the model is used): fastembed `BAAI/bge-small-en-v1.5`, 384 dimensions, local, cached in `workers/.cache`, on headline + snippet. Stored in `articles.embedding` (pgvector); readers can't select it (column grants list the readable columns: a new column on `articles` or `stories` needs adding to those grants to be readable).
- **Grouping** (`cluster/stories.py`): an article joins the nearest running story when its similarity to the story's centre is ≥ 0.75 **and** to one of its articles ≥ 0.80, within 72 hours; otherwise it starts a story. `merge_close` joins stories whose centres reach 0.85. Measured on 2,157 real articles (Nov 2026): cross-outlet pairs ≥ 0.75 were the same event 56/56; centre-only grouping let a summit story sprawl into neighbouring news, the member check fixed it. `tests/data/same_event_pairs.json` (98 hand-labelled pairs) and `test_grouping_quality.py` hold that line (precision ≥ 0.95, recall ≥ 0.80): re-measure before changing the model or thresholds. A story's title is the headline of a reputable outlet's news report closest to its centre, never an opinion piece's.
- **Topic catalog** (Nov 2026): 66 topics; 14 `featured` (chips in the wizard and settings, and the section menu), the rest found by searching their name or `aliases` ("soccer" finds Football, "f1" Formula 1; `lib/topic-search.ts`, unit-tested; `components/topic-picker.tsx`). A narrower topic has a `parent` it also counts for (Football → Sport, method `parent`), so broad pages never lose stories. Narrow topics need a higher match score (`NARROW_FLOOR` 0.58; broad 0.56). Measured on 4,431 real articles: about 93% of sampled narrow tags right after sharpening the confusable descriptions (UK politics caught any prime minister; rugby caught a football coach); 39% of articles have a topic (was 27%). Keep the original 18 slugs: readers' choices and links depend on them.
- **Topics** (`workers/data/topics.toml`; first 18 topics incl. Geopolitics and Architecture and cities): a precise feed section counts outright (business, markets, science, technology, sport, architecture, interiors; never "world" or "politics", which are relative to the outlet); otherwise a match with the topic's description only at ≥ 0.56 similarity (about 34/36 right, but only ~27% of articles), at most 2 per article. Stories take their articles' topics (`story_topics` view). Niche topics need specialist sources: the architecture press (Dezeen, Architects' Journal, Architectural Review, The Architect's Newspaper, Archinect; ArchDaily at tier 3) is in the registry for that. `enrich --retag` recomputes topics after editing `topics.toml`.
- **Running**: `python -m verilo_workers pipeline --loop` (fetch, enrich, group every minute; single steps: `ingest`, `enrich`, `cluster`, `sync-topics`). The desk lists the most widely covered stories with their leans, topics, articles (opinion and sponsored labelled, the rule on hover) and whether each meets the Phase 4 summary rule (`lib/sources.ts` `summaryReadiness`).

## Readers, front page and preferences
- **Who decides what:** readers choose what they see (topics to follow or mute, places, outlets to follow or hide, whether to show opinion pieces and tier 3 outlets). Tiers, leans, which outlets feed summaries, the balance rule and opinion detection are editorial and the same for everyone; summaries are shared per story, never per reader.
- **Tables** (`supabase/migrations/…04`, `…05`, `…07`): `reader_preferences` (regions, show_opinion, show_tier3, onboarded_at), `reader_topics` (follow / mute), `reader_sources` (follow / hide), each readable and writable only by its owner; `save_reader_preferences()` replaces a reader's whole set atomically (runs as the reader). `story_cards` view: one row per story with its articles (outlet, tier, lean, country, kind) and topic ids, for the front page.
- **Welcome wizard** (`/welcome`, signed in): topics, places, outlets (grouped by country, open for chosen places), what to show; every step skippable ("Skip for now" saves and marks the reader onboarded). New readers land there after the emailed link (`/auth/confirm` checks `onboarded_at`); returning readers go to `/`. **Settings** are My News (`/my-news`): the same sections on one page, plus muting topics. One client component for both: `components/preferences-form.tsx`; the server action `app/preferences/actions.ts` re-checks the session and validates with `lib/preferences.ts` `checkPreferences` (unit-tested) before the database function.
- **Ranking** (`lib/feed.ts`, pure, unit-tested): score = 0.35 importance (visible outlets, a fact-base report adds 0.1) + 0.25 freshness (12 h half-life) + 0.25 followed topic + 0.10 followed outlet + 0.05 places (share of outlets from chosen countries) + 0.10 reliability (tier). Hidden outlets, muted topics, and opinion or tier 3 when switched off are removed first; a single-outlet story appears only if it matches something followed. In the first 10: at most 3 per topic and 2 leads per outlet (deferred ones follow). "Also important today": up to 4 stories with 5+ outlets outside the reader's interests. 24 stories, then "You're caught up". Each card says why it's there ("You follow Geopolitics").
- **Front page** (`app/page.tsx`): everyone first gets the general page (no preferences), cached and part of the static shell; an onboarded reader's own ranking streams in its place. Visitors and readers not yet set up see the same "Make this front page yours" strip, so nothing moves. The lead story shows "How others reported it" (up to 3 other outlets, different leans first). **Story page** `/story/[id]`: every outlet's version with country, tier, lean and opinion labels (the AI summary goes here in Phase 4). `/about` is the explainer that used to be the front page.
- **Section menu and topic pages:** under the masthead, "Top stories" and every topic in `topics.toml` order (`components/topic-nav.tsx`; cached list, so it's in the static shell; the current section is marked with `aria-current` once the address is known; scrolls sideways within itself on phones). `/topic/[slug]` ranks that topic's stories with `rankTopic` (single-outlet stories kept, the reader's hidden outlets and display choices applied, a muted topic still shown on its own page). A story's topics (`story_cards.topic_ids`, migration `…06`) count only when at least 20% of its articles, and at least two, carry them (a one-article story keeps its article's): with one article enough, a 129-article summit story was "Business" because of one Bloomberg markets item. "Business" is named "Business and finance".
- **Caching** (`lib/news.ts`): stories cached for a minute and tagged `stories`; topics and outlets for an hour, tagged `reference`. `POST /api/revalidate` (Bearer `REVALIDATE_SECRET`, 16+ characters; 404 without it) refreshes them; the pipeline calls it after rounds with changes when `VERILO_REVALIDATE_SECRET` is set to the same value (`VERILO_REVALIDATE_URL` defaults to `http://localhost:3001/api/revalidate`). The tests' server gets a test secret and the tests call it after seeding (`refreshCaches`). Don't use short cache lifetimes for anything in the static shell: Next 16 treats a cache shorter than a few minutes as dynamic, which breaks prerendering.
- **Dev server gotcha:** the dev server's build cache (`apps/web/.next/dev`) can keep serving an old `globals.css` across restarts (seen twice). If styles don't change in dev, stop the server, delete `apps/web/.next/dev`, start it again. Production builds are unaffected.

## Run and test
```powershell
npm install; npm run db:start                 # repo root: local Supabase (needs Docker Desktop running)
cd apps/web; npm install; copy .env.example .env.local   # fill the key from `npx supabase status`
npm run dev                                   # http://localhost:3001
npm run check                                 # lint, types, format, unit tests, build, e2e, Lighthouse
npm test; npm run test:e2e; npm run lighthouse  # separately (e2e and Lighthouse need `npm run build` first)
cd workers; python -m venv .venv; .venv\Scripts\pip install -e ".[dev]"; .venv\Scripts\python -m pytest; .venv\Scripts\python -m ruff check .
.venv\Scripts\python -m verilo_workers sync-sources; .venv\Scripts\python -m verilo_workers ingest --loop
```
- Running the worker tests while `pipeline --loop` writes to the same local database can deadlock a pipeline round (seen twice); the round rolls back and the next one redoes the work. Harmless, but stop the loop for long test sessions.
- Worker tests: registry validation, parsing (full text never kept), polite fetching against a fake web (`httpx.MockTransport`), and `test_ingest_db.py` end to end against the local database (skipped when it isn't running). Tests that sync sources pass `scope=` so they never pause the real registry.
- Unit tests (Vitest, `apps/web/tests/unit`) include `contrast.test.ts` (WCAG contrast of every token pair, both themes) and `design-rules.test.ts` (no gradients, blur, shadows, rounding over 2px, emoji or hex colours outside `globals.css`).
- E2E (Playwright, installed Chrome, desktop and phone, `apps/web/tests/e2e`) runs against `next start` on port 3100 and the local Supabase: real sign-in through Mailpit (`sign-in.ts`), axe in light and dark, no sideways scroll, security headers, the theme button, the desk (404 for non-editors), the front page, story pages, the welcome wizard end to end, skipping it, and settings. Test data is arranged through `tests/e2e/supabase-admin.ts` with the local secret key, which `playwright.config.ts` reads from `supabase status`.
- Lighthouse CI (`lighthouserc*.json`, port 3200): mobile and desktop, performance / best practices / SEO 95+, accessibility 100, mobile LCP under 1.8 s.
- Every feature needs unit or worker tests, and anything on screen needs an e2e step with an axe check.

## Design rules (see `docs/style-guide.md`)
- Editorial, not SaaS: Newsreader for headlines, Public Sans for text, ink on warm paper, one oxblood accent. 12-column grid, 1200px, rules and whitespace between stories, not cards.
- Never: purple or indigo, gradients, glassmorphism or blur, drop shadows, corners over 2px, emoji icons, Tailwind or shadcn defaults (the default palette, scale, radii and shadows are cleared in `globals.css`), colours outside the tokens, endless scroll, autoplay.
- Server Components by default; client JavaScript only where a page needs interaction. Fonts through `next/font` (served from the site). Every interactive element keyboard-reachable with the accent focus outline; 44px touch targets; respect `prefers-reduced-motion`.
